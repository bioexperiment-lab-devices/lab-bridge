- Nav: Per-directory `_nav.yaml` manifests (PR #128), validated by `services/siteapp/app/docs_lint.py`.
- Verification: `python -m app.docs_lint`, local `uvicorn` smoke, manual visual pass on preprod.

## Authoring conventions (apply to every markdown page)

- **Voice.** Direct, second person, imperative for walkthroughs ("Open JupyterLab", "Edit `SerialHop_config.yaml`"). Declarative for architecture and security ("Caddy terminates TLS on 443 and proxies …").
- **Alerts.** `[!WARNING]` / `[!IMPORTANT]` reserved for foot-guns. `[!NOTE]` / `[!TIP]` sparingly.
- **Code blocks.** Always include language tag. Use the `title="…"` attribute (after the language tag, e.g. `` ```yaml title="SerialHop_config.yaml" ``) for filenames or where the context is the filename. Use `bash` for shell, `python` for Python, `yaml` for YAML, `mermaid` for diagrams.
- **Cross-section links.** Use absolute `/docs/…` URLs (e.g. `[lab name](/docs/admin/labs)`), never relative.
- **Anchors.** Auto-generated by the markdown-it anchors plugin from H2/H3 text. Choose stable headings; renaming an H2 breaks any external `#…` link.
- **No platform-launcher links** (JupyterLab, Grafana, Flasher, agent download) anywhere in the docs sidebar or page bodies unless contextually required (e.g. "visit `/grafana/` and check the lab-client-logs dashboard"). Quick-launch lives on `/`.
- **Length cap.** Pages should fit one print-screen of context per major heading. If a section grows beyond ~300 words, break a subheading off.

- [ ] Create the file with this structure:

  - **Intro paragraph:** one paragraph framing the diagram below — a single device call traverses notebook → chisel tunnel → SerialHop → serial bus → instrument → and back.
  - **H2:** `## Sequence diagram`. Include this mermaid diagram (verbatim — borrowed from the legacy `system-overview.md`):

    ````markdown
    ```mermaid
    sequenceDiagram
        autonumber
        participant N as Notebook
        participant T as chisel tunnel
        participant S as SerialHop
        participant I as Instrument
        participant L as Loki + Grafana

        Note over S: Boot — scan ports, dial VPS, open tunnels

        N->>T: client.discover()
        T->>S: POST /discover
        S->>I: probe bytes
        I-->>S: identity reply
        S-->>T: JSON device list

        I-->>S: reply bytes
        S-->>T: JSON response
        T-->>N: result

        S-->>L: stream logs (forward tunnel)
    ```
    ````

  - **H2:** `## What happens at each hop`. Numbered list, one paragraph per stage:
    1. **Lab PC boot.** SerialHop starts as a Windows service, scans serial ports, opens the chisel tunnel.
    2. **Notebook discover.** `client.discover()` becomes a `POST /discover` through the chisel reverse tunnel into SerialHop. SerialHop probes each port, identifies devices, returns a JSON device list. The Python client wraps these as `DiscoveredDevices`.
    3. **Device command.** `pump.pour_in_volume(5.0)` becomes a `POST /devices/{id}/command` through the same tunnel. SerialHop forwards the bytes to the serial port and returns the reply (when requested).
    4. **Log shipping.** SerialHop streams its own logs through a forward tunnel into Loki, where Grafana renders them in the lab-client-logs dashboard.
